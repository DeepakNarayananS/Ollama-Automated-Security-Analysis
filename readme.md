# Ollama Automated Security Analysis

A local security analysis toolkit using Ollama and the
Foundation-Sec-8B-Reasoning model.

The project currently provides two security analysis use cases:

1. Windows Security SOC Analysis
2. MCP Security Analysis

All AI analysis is performed locally through Ollama.

---

4. Create the Project
Create the main directory:

mkdir ollama_Automated_Security_Analysis
cd ollama_Automated_Security_Analysis

Create a Python virtual environment:

python -m venv .venv

Activate it:

.\.venv\Scripts\Activate.ps1

Install the dependency:

pip install requests

5. Verify Ollama
Check installed models:

ollama list

Run Foundation-Sec:

ollama run hf.co/fdtn-ai/Foundation-Sec-8B-Reasoning-Q4_K_M-GGUF:Q4_K_M

After confirming the model works, exit the interactive session:

/bye

The Ollama service should remain available locally.

The applications communicate with:

http://localhost:11434/api/generate

6. Windows Security SOC Analysis
Purpose
The Windows SOC analyzer collects selected Windows Security
events and sends them to Foundation-Sec for defensive analysis.

Currently analyzed event IDs:

4624 - Successful logon
4625 - Failed logon
4688 - Process creation

The model analyzes the collected evidence for:

Suspicious activity
Potential attack patterns
Risk
Evidence
Investigation steps
Defensive remediation
False positives
The model must only report findings supported by the supplied
Windows event data.

Windows SOC Structure
windows_soc/
│
├── windows_soc.ps1
│
└── reports/

The PowerShell script collects the Windows events and sends them
to the local Ollama API.

Windows SOC Prompt
Use:

Defensively analyze these Windows Security events for suspicious activity, attack patterns, and security risks. Provide severity, evidence, impact, investigation steps, remediation, and false positives. Report only what is supported by the logs—do not invent, assume, or hallucinate findings. Distinguish confirmed evidence from potential risks.

Run Windows SOC Analysis
From the project root:

.\windows_soc\windows_soc.ps1

Reports generated by the Windows SOC analyzer can be stored in:

windows_soc/reports/

and/or:

reports/windows/

7. MCP Security Analysis
Purpose
The MCP security auditor analyzes an MCP server as a defensive
security assessment.

The project includes an intentionally vulnerable local MCP lab
for security testing.

The lab should remain local and should not be connected to
real external services or sensitive data.

MCP Security Areas
The auditor focuses on:

Tool poisoning
Prompt injection
Indirect prompt injection
Toxic data flows
Sensitive-data exposure
Dangerous capabilities
Data exfiltration paths
External side effects
Excessive permissions
Authorization weaknesses
State-dependent behavior
Rug-pull behavior
Documentation vs implementation differences
Untrusted content
Trust-boundary violations
The scanner should distinguish between:

Confirmed vulnerability
Potential risk
Dangerous capability
Not demonstrated

MCP Structure
mcp_security/
│
├── mcp_lab.py
├── mcp_auditor.py
│
└── reports/

mcp_lab.py contains the intentionally vulnerable MCP
security-testing environment.

mcp_auditor.py performs the security analysis.

MCP Security Prompt
Use:

Defensively audit this MCP server for toxic data flows, tool poisoning, prompt injection, sensitive-data exposure, dangerous capabilities, and exfiltration paths. Provide severity, evidence, impact, and remediation. Report only findings supported by the code—do not invent, assume, or hallucinate vulnerabilities. Distinguish confirmed vulnerabilities from potential risks and capabilities.

Run MCP Analysis
From the project root:

python .\mcp_security\mcp_auditor.py .\mcp_security\mcp_lab.py

Reports can be stored in:

mcp_security/reports/

and/or:

reports/mcp/

12. Security Design
The intended architecture is:

                    Evidence
                       │
          ┌────────────┴────────────┐
          │                         │
          ▼                         ▼
   Windows Event Logs          MCP Source/Tools
          │                         │
          ▼                         ▼
   Windows Collector          MCP Auditor
          │                         │
          └────────────┬────────────┘
                       ▼
                Local Ollama
                       │
                       ▼
             Foundation-Sec 8B
                       │
                       ▼
              Security Analysis

The AI model should be treated as an analysis and reasoning
component, not as the authority that collects or executes
security actions.

Collection and execution should remain controlled by the local
PowerShell/Python tooling.

13. Important Safety Principle
This project is intended for:

Local security analysis
Defensive research
Windows SOC experimentation
MCP security testing
Intentionally vulnerable local labs
Do not provide the scanner with unnecessary access to:

Real credentials
Production secrets
Private keys
Sensitive personal data
Untrusted production MCP servers
Destructive system capabilities
The MCP lab should remain isolated and its simulated dangerous
actions should remain simulated during testing.
